`trainingday.r155_qwen_official_anchor` compares these external values to the
`observed_file_sha256` inventory generated by the existing **R140** local
file auditor. This catches an otherwise internally self-consistent R140
inventory referencing different weight/tokenizer bytes. It does **not**
replace R140's full safetensors index/header checks or hash the other
tokenizer/processor/template files against official values; those files still
need independent complete snapshot provenance.

The pure `assess_r140_report()` accepts an untrusted dictionary and returns
`UPSTREAM_DIGEST_CLAIM_MATCH_HOST_HOLD` even if the caller fabricated the
whole report, with all authority flags `False`. For an actual local snapshot
inspection the operator would invoke `audit_offline_against_official()` in
an authenticated host-owned process with external pins and verified immutable
file handles. That wrapper streams the whole R140-declared file inventory and
matches these three official digests, but remains a **host-custody HOLD** in
this source build. No genuine snapshot or complete 9.34 GB weight check was
performed here.

## Remaining independent boundaries

1. The host owner must authenticate the exact local full-model snapshot and
   tokenizer/processor/template files, control the root/namespace and keys,
   demonstrate unchanged handles across actual load, and bind the results to
   a signed immutable host receipt outside the trainer's rollback domain.
2. Before training, the official full multimodal configuration must be mapped
   through a tested text-only loader. The independently developed source-only
   [model-training #185](https://github.com/thebrazenbeard/model-training/pull/185)
   proposes that repair on the **different #182 stack**. Its synthetic loader
   test is not a real official-weight reload; integrate branches deliberately.
3. An authorized exclusive GPU lease and R19-01 NAS/Executor route, admitted
   data rights, independent evaluator, tokenizer/chat-template roundtrip,
   actual optimizer update, and checkpoint resume evidence must still exist.
4. After a genuine fine-tuned checkpoint, merge its declared adapter and
   convert/quantize to GGUF for Patrick's intended KoboldCPP runtime. Pin the
   exact converter/runtime revisions, hash output bytes, and compare frozen
   prompts/token IDs and logits or next-token behavior before release. A
   downloaded or existing filename ending `.gguf` is **not** proof of parity.

The R155 helper performs no network access, model download, CUDA operation,
weight materialization, GGUF conversion, optimizer step or protected-data read.
All tests use small synthetic R140 reports and cannot authorize training.
