`trainingday.r202_admission_candidate.inspect_r202_admission_request_candidate`
accepts only strict canonical UTF-8 JSON, exact R202 generator Git-blob SHA1,
TRAIN SHA256/count/schema, exact model revision and noncommercial purpose,

requires the steward, rights basis, all mandatory exclusions, and supplied
private DEV and exclusion-receipt commitments. It recomputes the public TRAIN
SHA from the installed generator. The **same identity** may fill both roles.

For `WITHHOLD`, it instead accepts **only the exact-source identifiers,
specified model/purpose, claimant name, and refusal decision**. It does not

Review requests additionally reject omitted exclusions and missing commitments.

## Falsifiers before integration

> **A rights-holder name in the file is not verified ownership.** Even an
> Ed25519 self-signed claim proves only that *some* key signed bytes. A key
> enrollment and provenance check outside this source code is still needed.

> **A matched DEV digest supplied by the trainer is not protected
> evaluation.** An adversary can generate a plausible fake commitment and
> satisfy all local source validations. The trainer must not choose/see the
> protected DEV seed, key, questions or answers.

> **A full row hash says nothing about semantic difficulty.** R202's current
> tool-intent class is keyword-separable even when its integer arguments are
> independently checked. Treat it as a six-domain narrow baseline, not a
> substantial verified general-reasoning curriculum.
